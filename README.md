# Muse

<img src="assets/muse.svg" width="64" alt="Muse logo">

简约的 Windows 桌面网络连接管理工具。使用 C++20 与 Qt Quick / QML 编写，提供无边框窗口、订阅管理、节点优选和应用连接规则。

当前版本：**0.5.1**。项目仍处于早期开发阶段，欢迎提交问题和改进。

## 功能

- **订阅管理**：添加、编辑、启停多个 Clash / mihomo YAML 订阅，支持手动与定时更新。
- **节点优选**：每次启动读取已启用的订阅并进行 HTTPS 延迟检测，选取本轮最低正延迟节点；全部超时时保留原选择。读取和测速不会自动打开连接开关。
- **应用连接规则**：未勾选应用时使用全局范围；勾选一个或多个应用后，仅为这些可执行文件应用连接规则，其他应用直接连接。
- **本机应用库**：从开始菜单、桌面快捷方式和应用注册信息发现桌面应用。未启动也能勾选，支持用途分类、运行状态筛选、搜索和手动添加。
- **订阅用量**：显示服务商提供的剩余用量、总量及到期时间；没有数据时明确标注。
- **TUN 与 HTTP/SOCKS**：支持 TUN 接管和遵循 Windows 系统连接设置的应用。应用选择使用完整可执行文件路径，同路径的多个实例共同生效。
- **操作反馈**：后台加载与测速、操作排队、选择保存失败回滚、退出清理和遗留设置恢复。

## 使用

1. 构建后运行 `dist/Muse.exe`。
2. 在「订阅管理」添加自己的 HTTPS 订阅地址。支持含 `proxies:` 内容的 Clash / mihomo YAML 格式。
3. 等待节点加载和延迟检测，或在「节点与测速」手动选择节点。
4. 在「程序分流」选择应用；没有选择时使用全局范围。便携应用可以通过「添加应用」导入 `.exe` 文件。
5. 在「概览」点击启动。默认使用 TUN；需要关闭时点击连接开关。

TUN 与应用连接规则需要管理员权限。请先退出 Muse，再右键以管理员身份运行。

本项目不提供远端服务和订阅。请使用你有权访问的服务，并遵守适用规则。

## 构建

运行环境：Windows 10 / 11 x64。

开发环境：Visual Studio 2022 的 C++ 桌面开发组件、Windows SDK、CMake 3.24+、Qt 6.8.3 MSVC2022 x64。首次下载依赖需要可用的网络连接。

```powershell
.\scripts\install-qt.ps1
.\scripts\install-core.ps1
.\scripts\build.ps1
```

构建脚本会运行测试，并将程序和所需运行库放入 `dist/`。核心程序默认从官方发布下载固定版本，并校验 SHA-256。源码仓库不包含运行库、核心二进制文件和个人配置。

已有兼容 Qt SDK 时，可自行指定路径：

```powershell
cmake -S . -B build-qt -G "Visual Studio 17 2022" -A x64 -DCMAKE_PREFIX_PATH="C:/Qt/6.8.3/msvc2022_64"
cmake --build build-qt --config Release --parallel
ctest --test-dir build-qt -C Release --output-on-failure
```

## 验证范围

测试包含配置与加密存储、应用发现与图标、选择保存与失败回滚、订阅队列定位、真实 QML 点击及多尺寸布局。存在 `core/mihomo.exe` 时，还会执行使用虚构本地节点的核心集成检查。

这些检查不打开本机连接开关。真实 TUN 路由、DNS、UDP、休眠恢复和网络环境切换仍需要进一步验证，不能用配置校验代替实际流量验证。

## 数据与隐私

便携数据保存在可执行文件旁的 `data/` 目录。请将程序放在当前账户可写的位置。

- `settings.dat` 与系统连接设置备份使用 Windows DPAPI 加密，绑定当前账户。
- 应用库缓存保存在本机，不会由 Muse 上传。
- 核心运行期间的 `runtime.json` 和 `providers/` 缓存可能包含服务地址及凭据；请勿提交或分享整个数据目录。
- 设置读取失败时会阻止覆盖原文件。请保留原文件并使用可用备份恢复，或将原文件移出数据目录后重新配置。
- 控制接口仅监听本机回环地址，使用每次生成的随机认证密钥。

提交问题前，请删除截图、日志和复现配置中的个人信息、订阅地址及访问凭据。

## 已知限制

- 暂不转换通用 Base64 内容或单条协议链接。订阅内的自定义路由、DNS 和脚本不会直接导入。
- 应用规则按文件路径匹配，不按 PID 区分。子进程和辅助组件具有独立路径时，需要分别选择；不承诺逐应用 DNS 隔离。
- 部分商店应用、网页快捷方式和游戏启动链接无法直接解析，需要手动添加实际可执行文件。
- 应用类别和节点地区是按名称推断的分类结果。应用运行状态在刷新应用库时更新。
- 仅使用系统连接设置时，覆盖范围取决于应用是否遵循这些设置。
- 尚无断线保护、后台服务、托盘、开机启动或实时带宽统计。核心退出后可能恢复直接连接。
- 不保证接管 ICMP、原始套接字、虚拟机和驱动产生的所有流量。
- 尚未经过独立安全审计。

## 代码结构

| 路径 | 职责 |
| --- | --- |
| `src/qt_bridge.*` | 界面状态、后台任务、操作队列与设置保存 |
| `src/engine.*` | 核心启动、就绪检查、连接启停与清理 |
| `src/config.*` | 设置格式、输入校验及运行配置生成 |
| `src/platform.*` | Windows 存储、进程、系统连接设置和本机控制接口 |
| `src/app_library.*` | 快捷方式和注册信息发现、应用库合并 |
| `src/app_icons.*` | 图标读取与缓存 |
| `qml/` | 页面、窗口和通用界面组件 |
| `tests/` | 配置、界面和核心集成检查 |
